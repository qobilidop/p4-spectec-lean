## Inputs and reproduction

P4-SpecTec is pinned at `8c8e0c6ffa604c533f5ad2f1db0503c0c601e6f3`.
Its `spec/` contains 108 `.watsup` files and 33,446 source lines. Upstream's
recursive directory traversal sorts entries and excludes `include/`.
Passing the directory to upstream preserves its own ordering policy;
the same exporter regenerates Nano-P4 byte-for-byte unchanged.

```sh
# In the upstream Nix shell, after scripts/build-upstream.sh:
scripts/export-spec.sh p4 upstream/p4-spectec/spec
# In the default Nix shell:
python3 scripts/spec-snapshot.py unpack exports/p4.al.json
lake exe p4spectec-census exports/p4.al.json --update .agents/notes/p4-census.json
lake exe p4spectec-census exports/p4.al.json --check .agents/notes/p4-census.json
lake exe check-quotes
```

The full export is 98,387,720 bytes (93.83 MiB), SHA-256
`803d798c13ae102e6aa970f65dfd2313d9d9b4094cae745049d3418c1af11953`.
It is stored as `exports/p4.al.json.gz` (2.61 MiB), with the raw checksum
in `exports/p4.al.json.sha256`. The JSON itself is an ignored working
file. `scripts/spec-snapshot.py` creates deterministic gzip (no filename
or timestamp) and verifies the checksum before publishing extracted JSON;
the gate extracts it automatically, without OCaml. Regeneration through
`export-spec.sh` refreshes both snapshot and checksum. No regions or hints
were removed. The checksum detects corruption or mismatched artifacts,
not a malicious coordinated replacement of both files.

This keeps a self-contained checkout while avoiding a raw file near
GitHub's 100 MiB limit. Compression sacrifices text diffs and does not
prevent history growth; review size and churn at upstream bumps. If that
becomes costly, move snapshots to checksum-pinned external artifacts
with a reproducible download/rebuild path. Nano-P4's 8.11 MiB JSON is
stored as a 244,303-byte gzip snapshot too, without rewriting history.
The gate rejects tracked/indexed files above 5 MiB, so growth requires a
storage decision before that threshold. Upstream itself tracks only small JSON
configuration/test fixtures at this pin, not these exported ASTs.

The export succeeds with upstream's `elab/dec-missing-clauses` warning
for `$sink<T>() : T` in `4-p4-ir/4.5-ir-to-surface.watsup`. The census
records `sink` as a function with no clauses; the current emitter produces
a failing computation for it. Its intended use/reachability needs an
explicit check during full-P4 validation.

## Current generation barriers

The ordinary generator rejects the unchanged full export at its explicit
stateful-planning guard in `Codegen/Emit.lean`. Stateful executable components
and bounded proof fixtures exist, but they are not integrated into production
planning. The checked census on retained main reports:

| Component | Result |
|---|---|
| Print hints | 190 occurrences on 67 types; all decode, validate and emit a literal table |
| Executable callable emission | 1,055 of 1,055 emit text |
| Inductive relation emission | 0 of 256 emit; the production proposition emitter rejects stateful mode |
| Subtype bridge emission | 567 of 567 instantiated pairs emit text (M3B; baseline 554) |

The earlier failures in `$replace_text'`, `$replace_text_except'` and
`$fresh_typeId` have component implementations. ByteText preserves arbitrary
bytes, and the fresh allocator uses explicit state. Root-index list and text
updates preserve base/replacement/index evaluation order and hard bounds
errors. Nested and sliced path updates remain rejected; neither occurs among
this pin's six indexed updates. Emitted text is not a whole-library build or
a certificate. The archived production aggregate's later casting-proof
failure is separate evidence, not a result of the retained main generator.
The thirteen baseline bridge failures all had source `continueResult`.
M3B's independent audits found the collector had erased its type
arguments: after instantiation the shared `_CONT` payload is exactly the
target payload in all 363 occurrences (105 injections, 129 projections,
129 checks). Every associated check is `MixopSC`; none is `RecurseSC`.
No payload conversion is required. Upstream `runtime/type/sub.ml`
substitutes both applications and requires equivalent case payloads.
The generator now preserves applications, specializes names and
signatures, and compares alias-normalized payloads after substitution.
Genuine mismatches, missing cases and malformed applications still fail.
The census records both heads and complete rendered application types.
Compiled synthetic regression fixtures cover two specializations of one
head pair; the full bridge set has only one specialization per head pair.

The print-hint slice ports alternation and note-aware printing, emits the
validated table as literal Lean data, and initializes the interpreter's
print extension from the same AL spec. All 2,120 case origins and 567
bridge pairs preserve optional hint policies; every CaseE must name an
actual variant/case when hints are active. The entire 190-entry table was
elaborated and compared with decoded policies. Twelve pinned upstream
observations run through printer, builtin and interpreter on each gate.
They exposed and fixed byte-escaping and ASCII-lowercasing discrepancies.
This checks static note changes, not arbitrary external input notes or
hinted-print refinement; `.agents/notes/print-hint-audit.md` details that
boundary and oracle reproduction.

These are **first-error diagnostics per independently probed component**.
Successful emission does not establish that a declaration type-checks,
that `partial_fixpoint` accepts it, that its theorem closes, or that it
agrees with upstream. Type declarations are sized, not elaborated; the
probe does not generate/test complete type encoders, decoders or modules.
Later errors can surface after an earlier rejection is fixed. None of
these probes substitutes for `p4spectec-gen --check` or the full gate.

## Quotation check delivered with M3A

`check-quotes` compares the actual compiled `NanoP4Spec.spec` against the
decoded export, using equality derived from the AST independently of the
reifier and its smart constructors. It ignores source regions and hints,
and omits source `VarD` entries as `Ctx.init` does. It preserves all other
structure, including expression/path type notes, type origins, relation
input positions, constructor identities and list order. It runs on every
gate invocation so changes to JSON cannot hide behind Lake's build cache.

The initial comparison caught a real namespace bug: the type `id.al`
contained the AST of function `$id`. Separating the type lookup from
callable lookup fixes quotation selection and type source-file placement.
All 342 expected Nano-P4 definitions now match. Sensitivity tests reject
changed payloads, notes, origins, input positions, missing/extra/duplicated
entries and reordered definitions. No full-P4 quotation is available to
compare until its generated library builds.

## Remaining M3 phases and exit criteria

1. **M3B: complete rendering and kernel checks.** Implement print-hint
   semantics, indexed/sliced path updates, the thirteen parameterized subtype
   bridges and stateful fresh type IDs. Resolve any elaboration failures
   in types, adapters and large recursion groups. Keep the per-source-file
   layout and audited run-soundness theorems. Exit: the unchanged full
   export generates, every module builds with `--wfail`, regeneration is
   byte-identical, the full-P4 quotation check passes, and per-module
   timing is recorded. The first slice preserves the thirteen
   `continueResult` specializations without relaxing payload invariance.
   The second slice supports hint-driven printing under checked policy
   compatibility. Next are the six indexed updates at this pin: two text
   replacements and four list replacements. No indexed prefix or slice
   update appears in the current export; unsupported synthetic forms must
   continue to fail explicitly until implemented.
2. **M3C: full-P4 differential validation.** Extend program exports and
   both Lean runners to upstream's P4 frontend, typing and instantiation
   relations, using upstream's exclusions. Port `Type.Equiv` for function
   values and settle the matcher/substitution fuel behavior. Test fresh
   IDs and print hints against upstream. Exit: explicit corpus counts,
   matching verdicts and outputs on both legs, and no unexplained
   differences. Add interpreter mutations and require this harness to
   detect them.
3. **M3D: targets and packet execution.** Start with NanoSwitch as the
   small exercise of the extern interface, then v1model and eBPF against
   their upstream STF tests. Record actual target coverage; PSA syntax
   in the export alone does not constitute a working PSA target. Exit:
   target instances plus reproducible upstream-versus-Lean packet results,
   with exclusions and failure cases accounted for.
4. **M3E: expand validation proofs.** Add builtin correspondence, type
   parameters, iteration and cast/subtype support in dependency-driven
   slices, followed by indexing, slicing, membership and externs. Preserve
   or represent any hints that become semantically relevant to printing.
   Bring the first real relation into the fragment early. Benchmark the
   proof driver in the full environment and address its simplifier setup
   cost before scaling. Exit: audited refinement proofs for the explicitly
   claimed scope and mutation tests showing a wrong translation is
   rejected. The thesis's all-definition claim remains open until no
   definition is excluded; a coverage percentage does not close it.
5. **M3F: determinism and proof usability.** Measure rule overlap and
   discharge disjointness obligations beyond the current single-path
   fragment. Report actual counterexamples or unresolved obligations
   separately from proven determinism. The completed field-update example
   proves reverse executable realization; it does not follow implicitly
   from run-soundness or determinism. Exactness of the logical relations and
   further completeness work beyond that slice remain separate questions.
   The first consumer proof is complete; P4Lib and broader
   downstream examples remain M4.

This order makes rendering failures, interpreter disagreements, target
work and theorem coverage independently measurable. M3A closes only the
reconnaissance and quotation-check work; these later phases remain open.

## Following the print-hint slice

Read-only AL census: 152 updates, of which 146 use only root/dotted paths
and six use `RootP/IdxP`. Two are text replacements in `$replace_text'`
and `$replace_text_except'`; four replace list values in `Lvalue_write`.
There are no slice updates or nested index prefixes at this pin.
Upstream evaluates the base, replacement, then path expressions; indexed
access checks bounds, and text replacement requires one byte. Existing
`Iter.setIdx` covers list updates. Text helpers currently use Unicode
characters where OCaml uses bytes; that must be considered explicitly,
not concealed by ASCII-only fixtures. Synthetic unsupported paths should
remain rejected until faithful general access/rebuild support exists.

Fresh IDs need real effects, not a pure placeholder. Upstream's
`Builtin.Call.Make` counter starts at zero per interface/process and
returns `FRESH__<old counter>` before incrementing. Its reset function has
no caller in the pinned library/binaries; ordinary interface initialization
does not reset it. Failed sequential alternatives consume identifiers:
backtracking does not roll the counter back. Any state encoding therefore
must carry updated state even on `Fail.unmatch`; putting state inside a
failure result that discards it would be wrong. Effect-interface design
is still pending, with codegen/Prop/refinement consequences to audit.
