## Design constraints

One Lake package. Use an existing module hierarchy by default; add a library
only for a concrete artifact/build boundary, and a package only for independent
distribution/dependency ownership. Remove empty P4Lib/P4Spec build targets;
those intended future homes remain available when their implementation arrives.
Preserve upstream mirror paths and generated spec filenames. Match Lean unit-test
paths to their owning code; colocate cross-language oracle suites and fixtures.
Preserve theorem statements/names/axioms, generated bytes, oracle identities,
case denominators and independent execution paths. Share plumbing, never the
semantic computation that an independent comparison is supposed to check.

## Execution and acceptance

1. Remove placeholder libraries, organize Lean tests, enforce dependency direction
   and transitive root/executable reachability with the existing header parser.
2. Colocate oracle suites; extract shared pinned-probe plumbing with explicit
   parameters, eliminate global mutation, preserve stronger caller contracts.
   Keep supported diagnostic entry points out of the test implementation tree.
3. Extract existing responsibility seams in compiler/certificate emission and
   refinement support. No new compiler IR or generalized proof algorithm.
4. Consolidate only tests with a demonstrated duplicate obligation. Retain
   semantic regressions, axiom audits, both differential legs, corpus cases,
   failure distinctions and distinguishing mutations.

Each coherent step receives independent read-only review. The full local gate
must exit 0 before publication; verify remote CI for the published revision.
No regeneration, upstream pin changes or Nano certification claim changes are
part of the refactor. Broader full-P4 work and the Nano reverse WIP remain paused.

## Implemented ownership

- Four nonempty libraries: core, generated Nano model, tests, examples. Standalone
  supported CLI roots are in `Tools/`; reusable checking logic stays in Codegen.
  The existing header-parser checker now enforces core/model/consumer direction
  and transitive reachability, including registered executable helpers. Removed
  the duplicate line-based direct-import checker.
- Lean tests follow subsystem ownership; Python infrastructure tests sit beside
  scripts; cross-language oracle suites are under `P4SpecTecTest/Oracle/`.
  Capture, replay and manual campaign entry points have distinct names.
- `Codegen/Exp/{Stmt,Context,Traversal}` own existing shared mechanisms;
  `Codegen/Certificates/{Forward,RunSound,StateForward,StateRunSound}` own
  certificate emission. Relation predicate generation stays in Props/StateProps.
- `Refine/{Eval,Environment,Syntax,ValueShape}` expose existing proof obligations;
  Calc retains an import facade for generated clients. Tactic Refine separates
  Normalize, Context, ForwardRules and Forward; rule presets remain explicit.
- Shared `oracle_build.py` takes explicit probe/scratch/link inputs. Shared
  `oracle_paths.py` resolves retained logical evidence IDs to moved source files.
  The Nano legs share only their identical expected-output JSON parser.

The gate remains the single explicit list of ordinary checks. Capture and manual
campaign commands live with their suites; no second test-discovery framework or
speculative library was introduced. Old proof/fixture declaration namespaces
remain stable even where test module paths improved.
